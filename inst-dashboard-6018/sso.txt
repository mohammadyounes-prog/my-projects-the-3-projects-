✦ I have fixed the "session expired" issue when navigating from the hub to the Question Retrieval app.

  Root Cause
  The frontend of the Question Retrieval app was incorrectly taking the raw sso_token (a UUID) from the URL and saving
  it directly as the access_token. Since the backend expects a JWT for authentication, it rejected the UUID, causing the
  session to appear expired immediately.

  Applied Fixes
   1. Corrected SSO Handshake: Updated home.html and index.html (in both the active instance and the project source) to
      properly exchange the sso_token for a valid JWT by calling the /verify-sso endpoint.
   2. Robust Verification:
       * The app now waits for the backend to verify the SSO session.
       * Upon successful verification, it stores the returned JWT in localStorage.
       * The URL is cleaned up (removing the token) after the exchange to prevent duplicate processing.
   3. Consistency: Applied these changes to the source frontend directory as well, ensuring all future instances created
      by the Config Manager will function correctly.

  You should now be able to click on the Question Retrieval app from the hub and be logged in automatically without any
  expiration errors.
